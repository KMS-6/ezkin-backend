# ADR 001: 서명된 사용자 토큰으로 선반 API를 보호한다

## 상태

Accepted

## 배경

기존 선반 API는 클라이언트가 보낸 `X-User-Id`를 신뢰해 다른 사용자의 UUID로 요청할 수 있었다. UUID는 인증 정보가 아니므로 사용자 소유 데이터에 대한 접근 제어가 성립하지 않았다.

## 결정

사용자 등록 시 서버 비밀키로 HMAC 서명한 Bearer 토큰을 발급한다. 선반 API는 토큰의 서명과 만료 시간을 검증한 뒤 토큰에 포함된 사용자 ID만 소유권 조회에 사용한다. 서명 비밀키는 `AAC_AUTH_SECRET` 환경 변수로만 주입한다.

## 고려한 대안

- `X-User-Id`와 공유 API 키: 구현은 단순하지만 모든 사용자가 같은 키를 가지므로 IDOR를 막지 못한다.
- 세션 또는 OAuth/OIDC: 장기적으로 적합하지만 별도 로그인·토큰 갱신·공급자 구성이 필요해 MVP 범위를 넘는다.
- 사용자별 HMAC 토큰: 별도 인증 공급자 없이 요청 주체를 검증할 수 있어 현재 단계에 적합하다.

## 결과와 트레이드오프

- 클라이언트가 임의 UUID만으로 다른 사용자의 선반에 접근할 수 없다.
- 토큰 만료 후 재발급·로그인 경로는 후속 구현이 필요하다.
- 비밀키가 노출되면 모든 토큰을 위조할 수 있으므로 저장소에 커밋하지 않고 Render 환경 변수로 관리해야 한다.
